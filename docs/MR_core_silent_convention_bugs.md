## 修正一：閘原語正規化（`27dc472`）

三個包裝函式與自身 docstring 矛盾：

| 函式 | docstring 宣稱 | 實際 | 差異 |
|---|---|---|---|
| `create_R_gate(t)` | `exp(-i t/2 (XX+YY))` | `R_spec(t/2)` | 因子 2 |
| `create_G_gate(t)` | `exp(-i t/2 (XY-YX))` | `G_spec(-t/2)` | 因子 2 且反號 |
| `create_CP_gate(t)` | 受控相位 | `CP_spec(-t)` | 反號 |

因子純屬包裝 qiskit 原語時未正規化的產物：`rxx(p) = exp(-i p/2 XX)` 且 `XX` 與 `YY`
對易，故 `R_spec(t)` 就是 `rxx(t)·ryy(t)` —— 那個多出來的 `/2.0` 即是全部病灶。
`build_annealing_circuit` 在呼叫端以 `-2.0*tau*w` 抵銷，所以物理一直是對的。

正規化後呼叫端的因子直接消失：

```diff
-                    theta_R = -2.0 * tau * w_R
-                    theta_I = -2.0 * tau * w_I
+                    theta_R = -tau * w_R
+                    theta_I = tau * w_I
-                        theta_U = -tau * ramp * current_U
+                        theta_U = tau * ramp * current_U
```

### 驗證：逐位元相同

送進 qiskit 的 `rxx`/`ryy`/`cp` 角度是**同樣的浮點數**，電路是同一個物件：

```
1. 原始電路指令串（名稱 + qubits + 角度，12 位小數）
  [IDENTICAL] N2_PBC_U0.0-0.0  (109 instructions)
  [IDENTICAL] N2_PBC_U0.5-1.3  (125 instructions)
  [IDENTICAL] N3_OBC_U1.0-1.0  (201 instructions)
2. 態向量        [IDENTICAL]
3. 物理可觀測量  berry / polarization / fidelity 全部 [IDENTICAL]
```

重現：`tests/verify_gate_norm_equivalence.py`

## 修正二：Slater 行列式態製備（本次新增）

`_givens_instruction` 原以下列電路分解實作：

```python
gv.rz(phi, 1); gv.rz(-phi, 0); gv.cx(0, 1)
gv.cry(-2.0 * theta, 1, 0)          # <-- 應為 +2.0 * theta
gv.cx(0, 1)
```

兩個獨立缺陷：

1. **`cry` 反號** → 製備出由**最高**單粒子軌域構成的行列式態。
   在具手徵對稱性的 SSH 鏈上，最高與最低軌域能量互為精確負值，
   因此製備態能量為 $+E$ 而非基態能量 $-E$。

2. **`rz` 結構對複數躍遷根本不對**。這點與缺陷 1 有本質差異：
   $\varphi = 0$ 時舊版恰為 `correct(-theta, 0)`，是純重參數化；
   但 $\varphi \neq 0$ 時，241×241 全域掃描找不到任何 $(\theta', \varphi')$
   能重現正確的閘（最佳殘差 **0.64**）。舊版讓 $|11\rangle$ 停在相位 $1$，
   而正確版應為 $\det G = e^{i\varphi}$ —— 它是另一族閘，不是「參數放錯的 Givens」。

改以 OpenFermion 慣例的 Givens 么正矩陣直接建構：
$|00\rangle$ 不變、單佔據子空間套用 $G$、$|11\rangle$ 乘上 $\det G$。

### 為何長期未被發現

`fidelity_scan` 是唯一碰到態製備的既有檢查，但它以**製備態本身**為參考比較演化後的態
—— 自我參照，對「製備了哪一個行列式態」完全不敏感。修正前後其輸出在物理上完全相同
（最大絕對差 $6.7\times10^{-16}$，純屬 `UnitaryGate` 與分解電路的浮點捨入路徑不同）。

## 修正三：CUDA-Q 後端位元序（`1138e05`）

`CudaqBackend.statevector` 將 qiskit 量子位元 $i$ 映射至 CUDA-Q 的 $n-1-i$，
理由是註解所稱「CUDA-Q 以量子位元 0 為最高有效位元」。**這句話只對了一半，
而錯的那一半正好是關鍵的一半。**

CUDA-Q 自身對量子位元順序並不一致：

| CUDA-Q 介面 | 慣例 | X 作用在 q0（3 qubits） |
|---|---|---|
| `get_state()` 振幅索引 | **小端序** | index `1` |
| `sample()` 位元字串 | **qubit 0 在最左** | `'100'` |

而 qiskit 的 `counts` 是 qubit 0 在**最右**（`'001'`）。
也就是說兩個函式庫在**字串**慣例上相反，在**索引**慣例上卻完全一致。
舊註解描述的是字串行為，卻套用到了態向量上，因而注入了多餘的反轉。

實測：3 量子位元 kernel 上 X 作用於 q0/q1/q2 分別得到索引 1/2/4，
與 qiskit 完全相同（`nvidia`、`nvidia-fp64`、`qpp-cpu` 三個 target 皆然）。
正確映射是**恆等映射**。

### 影響

所有**非位元反轉對稱**電路的 GPU 結果先前皆為錯誤。

| | 修正前 | 修正後 |
|---|---:|---:|
| `aqs selftest --backend cudaq` | 0.18124364 | **1.00000000** |
| 30 組隨機非對稱電路最差保真度 | 0.0010182006 | **1.0000000000** |

qiskit 後端不受影響。

## 修正四：OpenFermion → qiskit 位元序（`12b86ce`）

`openfermion.get_sparse_operator` 把量子位元 $q$ 放在位元位置 $n-1-q$（**大端序**，
`FermionOperator` 與 `QubitOperator` 皆然），而 qiskit 的 `Statevector`
—— 以及 `observables.PROPERTIES` 中所有函式 —— 放在位元位置 $q$。
`measure_hamiltonian` 未做任何轉換就把基態交給可觀測量，
因此 operator 格式檔案的每一個回報量都是**位元反轉**的。

實證：在四模式鏈的模式 0 設下深位能井，其密度卻在 qubit 3 被讀出。
對 spinless 佈局而言，反轉同時**交換 A/B 次晶格**（偶↔奇 qubit 索引）
並**倒轉晶胞順序**，所以極化分布是被取負且前後顛倒的：
cell 0 回報 $-0.2488$，實際應 $> 0.5$。

### 修正

`load_hamiltonian` 改以置換相似變換 $H \to P H P^T$ 回傳小端序算符。
$P$ 為置換矩陣，故此變換**嚴格保持全部本徵值**
（於陷阱鏈驗證至 $1.8\times10^{-15}$，並以 $n=2..4$ 隨機 Hermitian 矩陣覆核），
基態能量不受影響，改變的只有基底標記。

矩陣格式（`dense_matrix` / `sparse_matrix`）**刻意不轉換** ——
其慣例由呼叫者自行決定。

### 影響

| 對象 | 影響 |
|---|---|
| 內附兩個範例 | **無**。密度均勻（每格 0.5），位元反轉在其上是恆等操作；實測差異 $\leq 6.7\times10^{-14}$。 |
| 任何非對稱哈密頓量 | **先前結果全錯**。 |

這也解釋了此缺陷為何長期未被發現 —— 唯二的內附範例在結構上就無法偵測它。

  $-E$，斷言會翻號而非漂移，不可能漏看。

## 一個容易再犯的陷阱（已寫入註解）

推導 $G$ 閘符號時務必注意：`openfermion.get_sparse_operator` 是**大端序**，
對兩模式系統會交換模式 0 與 1 並**悄悄共軛**帶 $\mathrm{Im}(t)$ 的非對角元。
實部項 $XX+YY$ 在交換下不變，因此**不會**暴露錯誤。

本專案的 `_G_SIGN` 就曾因此被設成錯誤符號。測試刻意在內部自建小端序參考矩陣
（而非 import 輔助函式），以免相依於其他分支。

## 與另一分支的交互作用（合併前必讀）

`fix/cudaq-bit-order-and-uv-migration` 新增的 `src/aqs/spinless.py` 以**舊慣例**
呼叫這些原語：

```python
th_R = -2.0 * dt * t_re
th_G = _G_SIGN * 2.0 * dt * t_im     # _G_SIGN = -1
qc.append(create_CP_gate(-dt * model.V_v * lam), ...)
```

兩分支若未經協調各自落地，`spinless.py` 會**靜默**錯掉。這已實測過：

| | 正常 | `core.py` 正規化但 `spinless.py` 未更新 |
|---|---|---|
| 絕熱收斂 $T=20, L=800$ | 0.99988331 | **0.930398** |

**git 不會標記衝突** —— 兩分支改的是不同檔案，只有語義衝突沒有文字衝突。
後合併者必須改為：

```python
th_R = -dt * t_re
th_G = dt * t_im                      # _G_SIGN 不再需要
qc.append(create_CP_gate(dt * model.V_v * lam), ...)
```

另註：該分支已獨立修正 `_givens_instruction`（同樣的正確矩陣），
故本 MR 的修正二與其為**相同內容**，rebase 時應可自然吸收。

建議順序：先合本 MR，再 rebase 另一分支，並重跑其驗證套件
（態製備保真度 1.0、絕熱收斂 $\geq 0.9997$）。
